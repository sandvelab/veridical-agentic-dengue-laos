04_retrain

How often is a model refitted across the backtest? Chap's n-retrain governs whether one fit serves all splits or each split gets its own.

Answers

**The sibling is built and run.** Refitting at every split gives **+0.1651** against the main path's +0.1485: it helps our pool a little and does not help the reference. That asymmetry is the paragraph below made quantitative — the reference already refits inside `predict`, so the flag buys it nothing and costs it eight times the compute. See `b_everySplit/claim.md`.

`n_retrain = 1` reaches `chap eval` from a file rather than from a constant in each model's runner, so two models cannot disagree about it silently. The flag governs how often chap-core calls `train`; it does not stop a model that fits inside `predict` from refitting at every split, which is what the reference model does. That distinction is recorded because one flag can otherwise look as though it had made all the models comparable in this respect.

Children alternatives

Only the main path is run by this node. The others are run by the stability node.

  • a_once main path
    Refit once, at chap-core's default n-retrain 1: a single fit on the training period, with an expanding historic window handed to predict at every split.
  • b_everySplit not taken
    Refit every model at every split rather than once, by setting chap-core's n-retrain to the number of splits. A forecast made in 2009 is then made by a model that has seen 2008, which is more like how a forecasting system is actually operated and is what the reference model does inside its own predict.
